# Zagros v1.0.0-alpha.8.7

## Release summary

Alpha 8.7 consolidates the Phase 1–5 release cycle: independent PPP providers,
SoftEther lifecycle hardening, outbound persistence and routing isolation,
real routing/accounting/quota coverage, and the final SSTP compatibility and
outbound-test contract fixes.

This is an alpha release. Back up before upgrading and review the capability
and security documents before enabling legacy protocols.

## Independent providers

The following are independent Linux client/server providers. They are not
SoftEther protocol aliases:

- `l2tp_ipsec`: strongSwan/XFRM + xl2tpd + PPP, fixed UDP/1701.
- `l2tp_raw`: xl2tpd + PPP, fixed UDP/1701; no confidentiality and requires
  explicit legacy-risk acknowledgement.
- `sstp`: `sstp-client` + the packaged PPP plugin, mandatory certificate and
  hostname validation.
- `pptp`: independent ACCEL-PPP server and independent PPTP outbound client;
  legacy/insecure and requires explicit acknowledgement.

PPTP server control is fixed to **TCP/1723** plus GRE protocol 47. The
unmodified reference PPTP client cannot support a custom control port; no
proxy, REDIRECT, DNAT or patched-client workaround is included.

SoftEther PPTP remains unsupported by SoftEther. No SoftEther PPTP server or
client capability is fabricated.

## SoftEther lifecycle and routing

- SoftEther `UserCreate` duplicate/error-66 handling is idempotent and
  retry-safe.
- `vpncmd UserList /CSV` parsing is used for account replay and reconciliation.
- Existing accounts reconcile password and expiry state without blind duplicate
  creation.
- Native SoftEther client namespaces, VRFs, marks, routes, adapters, counters
  and cleanup are isolated and restart-safe.
- L2TP/IPsec, raw L2TP and SSTP server-side SoftEther listeners remain distinct
  from their independent outbound client providers.
- Deprecated SoftEther outbound aliases are not selectable in the catalog:
  `softether_l2tp`, `softether_l2tp_raw`, `softether_sstp` and
  `softether_pptp`.

## Outbound persistence and security

- Outbound credentials are sealed at rest and redacted from public API views.
- Secrets are kept out of argv and public diagnostics.
- PPP profiles use private mode-0600 runtime files; custom SSTP CA material is
  public certificate material only.
- No Docker socket or new privileged mode is introduced.
- No database migration is required for this release.

## SSTP compatibility fix

The runtime image contains `sstp-client 1.0.20`, whose supported certificate
options include `--ca-cert` and `--ca-path`, but not `--ca-dir`. The outbound
command builder no longer emits `--ca-dir`. With the system trust store it
lets the client use its compiled system CA path; with a private CA it emits
only the supported `--ca-cert` option.

Certificate verification, hostname validation, SNI, PPP plugin callback and
cleanup remain enabled. `--no-verify`, `--cert-warn`, `verify=false` and
insecure TLS are not supported.

## Outbound Test contract

The public Test result is intentionally small:

```json
{
  "status": "healthy",
  "rtt_ms": 123.456
}
```

The dashboard renders only:

```text
healthy · RTT 123.456 ms
```

Setup time, PPP readiness, first packet, p95 and HTTPS request duration are
internal diagnostics, not user-facing delay metrics. RTT is measured after
readiness using real ICMP probes through the provider interface, with warm-up
probes followed by a fixed measurement window. A failed measurement returns
`status: unhealthy` and no stale RTT.

## Verification

The Phase 1–5 test evidence includes:

- full Python suite: 945 passed, 8 skipped;
- Phase 5 targeted tests: 67 passed;
- real VPS SSTP, L2TP/IPsec and PPTP provider tests;
- real browser checks with zero console/page errors for the configured SSTP and
  L2TP/IPsec outbounds;
- routing, accounting, quota, lifecycle and negative-provider coverage;
- dashboard typecheck and production build;
- CLI and installer gates from the release-cycle evidence.

Raw L2TP never reports a fabricated healthy result. It requires a real endpoint
with raw-L2TP service enabled; otherwise the provider fails closed.

## Upgrade

```bash
sudo env ZAGROS_SCRIPTS_REF=v1.0.0-alpha.8.7 \
  bash -c "$(curl -fsSL https://raw.githubusercontent.com/ZagrosGM/zagros-scripts/v1.0.0-alpha.8.7/zagros.sh)" \
  -- update --version v1.0.0-alpha.8.7
```

The release image is published only after the release workflow completes its
full test, multi-architecture build and GHCR publication gates.
